## Findings

### [LOW] `ImplStatus` / `SourceSpan` are not re-exported from the conformance crate
**Category:** test-gap / API ergonomics
**Description:** Spec ac-02 says `ImplStatus` and `SourceSpan` are "re-exported from `brightfield-spec`". `crates/brightfield-conformance/src/lib.rs:30-41` re-exports most types (`ComponentIdentity`, `Surface`, `SupportReport`, …) but does not re-export `ImplStatus` or `SourceSpan`. Downstream consumers must take a direct dependency on `brightfield-spec` to construct or destructure a `SupportEntry`.
**Evidence:** `crates/brightfield-conformance/src/lib.rs:30-41` — no `pub use brightfield_spec::{ImplStatus, SourceSpan};` line. `crates/brightfield-conformance/src/support.rs:9` imports them locally.
**Recommendation:** Add `pub use brightfield_spec::{ImplStatus, SourceSpan};` to `lib.rs` to satisfy the spec wording exactly. Non-blocking — all tests construct via `brightfield_spec::ImplStatus::Unimplemented` directly and pass.

### [LOW] Curated preflight accounting is name-level, not identity-level
**Category:** spec-interpretation
**Description:** ac-16 says "every blocking entry's `ComponentIdentity` is accounted for in a deviation registry entry whose `affected_specs` list names the entry." The current gate (`tests/curated_preflight.rs:61`) only checks that *some* deviation names the filename in `affected_specs`; it does not verify the `ComponentIdentity` appears in any registry field. The implementer explicitly rationalises this in `progress.md` and the test's own doc-comment, arguing the accounting handle in v1 is filename-level because the registry doesn't yet carry a `component_identities` field. V1 correctness is preserved: DEV-0001 is a catch-all bootstrap whose `affected_specs` covers all 10 curated specs; the coarser check still gates "no curated spec may have an unaccounted-for unimplemented component". When per-component deviations replace the bootstrap in a later card, tightening this gate to identity-level will be necessary.
**Evidence:** `tests/curated_preflight.rs:61-68`; `progress.md:36-41`; spec ac-16 text (line 322-330).
**Recommendation:** Non-blocking for v1. File a follow-up card to add `component_identities: Vec<ComponentIdentityRef>` to `Deviation` and tighten `dfconf_curated_preflight_accounted` when the renderer card starts flipping specific `ImplStatus` values to `Implemented`.

### [LOW] `dfconf_observed_corpus_points_at_brightfield_spec` test name vs. spec's `OBSERVED_CORPUS` const usage
**Category:** cosmetic
**Description:** The test name matches the spec; implementation is correct. No action.
**Evidence:** `src/corpus.rs:157`.
**Recommendation:** None.
