## New Findings

### [MEDIUM] M1 — The literal-radio height formula and the default-prepend rule collide: an unlisted param default renders one more 22px row than the layout reserved, and every specified test passes over it

**Category:** constraint-conflict / failure-mode
**Pass:** 3
**Description:** Two v1.1 amendments compose badly. diw-ac04 (per the folded prior-L3) now explicitly prepends the param default onto a **literal** `options:` list when absent ("prepend-on-absent for BOTH a derived list AND a literal list omitting the default"), and decisions_locked #6 pins that reconciliation runs BEFORE style finalisation. diw-ac05 sizes a literal-N radio at `22·N + RADIO_CHROME_PAD` at **layout_component's Input arm** — and `layout_component(component: &Component, x, y)` (layout.rs:163) sees only the Component, never the params block, so N is necessarily the spec's literal count, pre-reconciliation. A radio with literal options `[a, b, c]` and param default `d` therefore lays out at `22·3 + 10 = 76px` but renders 4 rows = 88px post-prepend: the last option overflows its rect by 12px (RADIO_CHROME_PAD 10 < row height 22), overlapping whatever the dashboard bounding-box fold (main.rs:1116-1130, which chains layout rects) placed below — or, if the radio is bottom-most, clipping at the window edge. The ordering decision that fixed H1 names a post-prepend rule for **checkbox** (≠2 → degrade) but none for radio; diw-ac14's degrade enumeration covers derived-options radio but not prepended literal radio. Every test the spec names passes without exercising the composition: ac05 pins the formula from literal N ✓, ac04 pins the prepend ✓, ac14 pins its enumerated degrade list ✓ — user-visible geometry fails anyway. This is the exact "passes tests while user-visible behaviour fails" class, introduced (or rather made concrete) by the v1.1 amendments themselves.
**Evidence:** spec diw-ac04 verification ("a literal list omitting the default") + diw-ac05 description ("literal N-option list gets height 22·N + RADIO_CHROME_PAD") + decisions_locked #6 (checkbox-only post-prepend rule); layout.rs:163 (`fn layout_component(component: &Component, x: f64, y: f64)` — no params visibility; `compute_layout` at :155 has the Spec but the AC anchors the Input arm); main.rs:1116-1130 (bounding box folds layout rects).
**Recommendation:** Pick and pin one composition rule, cheapest first: **(a — recommended)** extend style finalisation symmetrically: a `style: radio` whose post-reconciliation option count exceeds its layout-time literal N degrades to menu presentation with a runtime Log Warning (one sentence in decisions_locked #6, one entry in diw-ac14's degrade list, one assembly-level test; the slack of a radio-tall rect hosting a 32px menu is cosmetic and safe — no overlap). The degrade fires only on the same authoring-inconsistency class the slider clamp handles, so it is rare and honest. Alternatives: (b) thread params into the Input sizing (a signature change to a pure spec fn — larger and unanchored), or (c) declare the prepended radio renders N+1 rows within the rect — false as constants stand. Whichever is picked, add the composition test (literal radio + absent default → the pinned behaviour) to diw-ac04 or ac14's verification.
