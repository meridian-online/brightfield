## Findings

### [INFO] sqlparser version differs from spec text
**Category:** doc
**Description:** ac-12 specifies `sqlparser = "0.55"` but the implementation uses `0.61`. The spec text says "0.55 (or latest stable)" so this is within the stated latitude. 0.61 is newer and has broader DuckDB dialect support.
**Evidence:** `crates/brightfield-sql/Cargo.toml` line 14: `sqlparser = { version = "0.61", features = ["visitor"] }`
**Recommendation:** No action needed. The parenthetical "(or latest stable)" explicitly permits this.

### [INFO] Bin.width is String instead of f64
**Category:** design
**Description:** The spec's ac-01 describes Bin as carrying typed fields but does not specify width's type. The implementation uses `String` instead of `f64` because `f64` does not implement `Eq` or `Hash`, which are required derives for `QueryPlan`. This is documented in progress.md as a deliberate detour.
**Evidence:** `crates/brightfield-sql/src/ir.rs` line 122: `width: String`; progress.md detour entry.
**Recommendation:** No action needed. Sound engineering trade-off to preserve the Hash-based shape-cache requirement.

### [INFO] Layer 2 conformance fully activated
**Category:** enhancement
**Description:** The branch correctly activates layer-2 conformance (DDL equivalence) for all 10 curated corpus specs. The previous stub returning "SQL emitter not yet available" is replaced with actual emission + fixture comparison. All `.layer2.expected.sql` fixtures and `.expected.yaml` files updated. DEVIATIONS.md updated with DEV-0002 (DuckDB ATTACH READ_ONLY divergence) and layer suppression adjustments.
**Evidence:** `dfconf_cli_layer_2_curated_all_pass` test passes; 10 `.layer2.expected.sql` fixtures committed.
**Recommendation:** No action needed.

### [INFO] brightfield-conformance now depends on brightfield-sql
**Category:** architecture
**Description:** The conformance crate gained a dependency on brightfield-sql to call `emit_sources` and `canonicalise_ddl` for layer-2 checks. This creates a one-way dependency chain: conformance -> sql -> spec. No circular dependencies.
**Evidence:** `crates/brightfield-conformance/Cargo.toml` line 12: `brightfield-sql = { path = "../brightfield-sql" }`
**Recommendation:** No action needed. Architecturally sound.
