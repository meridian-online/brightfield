## Findings

### [LOW] CI band geometry properties not directly asserted in ac-05 test

**Category:** test-gap
**Description:** Spec ac-05 verification states "assert the CI band geometry has 32 sample points with non-monotonic widths (narrowest at x_bar, widest at extremes)". The implementation in `RegressionRenderer` does sample 32 grid points and computes the analytic `se(ŷ|x) = s·√(1/n + (x-x̄)²/sxx)` formula correctly (mark.rs RegressionRenderer block), but the test `gomb_ac05_regression_renders_line_and_ci_band` only asserts `path_tags.len() > 0` and the slope/intercept math. The non-monotonic-width property of the CI band itself is not asserted.
**Evidence:** `crates/brightfield-render/src/mark.rs:1530-1543` — assertions are limited to `path_tags > 0` and the Anscombe slope/intercept reconstruction.
**Recommendation:** Acceptable as-is for this slice (the analytic formula is well-known and can be unit-tested in a follow-up if regression appears). The visible behaviour through scene encoding is captured.

### [LOW] Density renderer scene assertions are coarse

**Category:** test-gap
**Description:** Spec ac-04 says "assert the scene contains exactly 256 circles (16*16 cells)". The `gomb_ac04_density2d_renders_circle_grid` test uses a 3×3 grid and asserts only `path_tags.len() > 0`. Similarly ac-03 says `count_scene_fills > 0` — implemented as `path_tags.len() > 0` which is a weaker but functionally adequate proxy.
**Evidence:** `crates/brightfield-render/src/mark.rs:1424-1458, 1376-1422`.
**Recommendation:** Acceptable — Vello's `path_tags` covers both fills and strokes; the renderer empirically draws one circle per cell (per the for-loop body in `Density2DRenderer::render`), and the path-tag count being non-zero confirms the loop ran. Tightening to "exactly 256 circles" would require access to scene-internal counters that Vello does not expose stably.

### [LOW] ac-13 snapshots are substring assertions, not file-anchored snapshots

**Category:** test-gap
**Description:** Spec ac-13 calls them "snapshot tests" with on-disk files. The implementation uses inline `assert!(sql.contains(...))` for each structural piece (width_bucket, regr_slope, GROUP BY shape, etc.). Functionally equivalent for catching SQL regressions, but technically a different test idiom from `insta`-style snapshots.
**Evidence:** `crates/brightfield-sql/src/emit.rs:511-576`.
**Recommendation:** Acceptable for this slice. The substring assertions are stricter in intent (they pin specific tokens regardless of whitespace shifts), and the conformance crate's existing snapshot infrastructure was not extended in this slice. If a future card adds true snapshot files, these tests can migrate.

### [LOW] gomb_ac09 vocab status check is implicit, not a dedicated test

**Category:** test-gap
**Description:** ac-09 verification says "Unit test (gomb_ac09_vocab_status_flipped): instantiate the vocab registry and assert MarkKind::Density, DensityX, DensityY, RegressionY, RegressionX have status == Implemented". No test with that name exists; the property is verified indirectly by the parse and lower tests succeeding (an Unimplemented kind would fail at parse time per existing surface checks).
**Evidence:** `rg fn gomb_ac09 crates/` returns no matches; vocab flip is in `crates/brightfield-spec/src/vocab.rs`.
**Recommendation:** Add a one-line test in vocab.rs in a follow-up if explicit status assertion becomes important. Today the corpus parse gate (ac-16) effectively verifies the flip didn't break anything, and the gomb_ac06/07/14 tests would all fail if the kinds were still gated as Unimplemented.

## Honest Assessment

The implementation lands the statistical-marks slice cleanly with a hybrid SQL+Rust compute split that matches D1, no new dependencies (D6 honoured), and a renderer-side LRU cache that satisfies the D5 cache-hit invariant.
