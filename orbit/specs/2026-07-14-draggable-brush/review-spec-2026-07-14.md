## Must-fix — RESOLVED in v1.1

1. **The silent-no-op defence (drb-ac07) was toothless — the exact card-0021 trap it names (HIGH testability + HIGH completeness + MEDIUM load-bearing, all converging).** Verified: `commit_brush` needs `cx: &mut App` and returns `false` for any non-`Brushing` state (`_ => return false`, crossfilter.rs:290), and its only call site is the cx-bound mouse-up closure (chart_element.rs:196) — *not* headless-reachable. So a move/resize ending in `Selected` re-dispatches only if a `Brushing` is synthesised from the new corners, yet the spec's own open_question #3 + constraint *sanctioned* siting that synthesis in the un-headless mouse-up caller. A headless drb-ac07 written that way must hand-build a `Brushing` and feed `commit_brush_release_multi` — proving the *primitive* inverts a rect (already true, already tested by cfs2_ac11 / drag_skips_point_bindings) while never exercising the NEW move/resize→`Brushing` wiring. A wiring where release updates the grey overlay but never synthesises a `Brushing` would pass drb-ac07 green — the precise card-0021 failure recurring, on the card's single most-emphasised risk (evaluation principle #2, weight 0.2), backstopped only by Hugh's eyeball.
   → **Fix:** the move/resize→`Brushing` synthesis is now a PURE, gpui-free production fn `redispatch_brushing_from(end_state) -> Option<InteractionState::Brushing>` beside the transforms in interaction.rs's plain `#[cfg(test)]` scope (new **drb-ac12**, mirroring drb-ac05's grab resolver). drb-ac07 rewritten to DRIVE that production fn: (a) the input is a MOVED `Selected` end-state produced by the drb-ac03/04 transform (not hand-built corners), with a delta that *provably crosses a datum* so `N2 != N1` is guaranteed, not incidental; (b) only the derived `Brushing` is fed through `invert_pixel_brush → commit_brush_release_multi`, asserting `P2 != P1` and `N2 != N1`; (c) a NEGATIVE CONTROL — a raw `Selected` routed through the unchanged release path dispatches nothing (empty aggregate, chart_view.rs:290) — so the test *fails if the synthesis wire is missing*. Constraint 4 now REQUIRES the pure fn and FORBIDS inlining the synthesis only in the mouse-up closure; the constraint-2 purity enumeration gains it; open_question #3 marked RESOLVED (the two impl options — caller-calls-it, or a widened `commit_brush` that calls it internally — both must DRIVE the pure fn); the risk[0] mitigation overclaim is corrected.

2. **drb-ac05 grab-before-brush is untested at the seam it now shares with drb-ac06's frame_area clamp (MEDIUM, testability).** `drb-ac06` retargets the clamp to `frame_area` (margins only), so a boundary brush can now have an edge up to `DEFAULT_SCALE_INSET` (5px) ABOVE `plot_area.y0` — inside the inset band where `contains()` is false today (chart_state.rs:262 gates `pointer_down` on `contains → plot_area`, chart_layout.rs:162-164). drb-ac05 takes plot-contains as an input, and its enumerated cases genuinely conflict for that overhang press ("Grab when region != Outside" AND "Ignore when outside the plot" both hold), but none disambiguate it. An implementer who short-circuits on plot-contains first (a reasonable reading) makes the boundary-edge/corner handles un-grabbable — its whole `HANDLE_TOL` band sits in the overhang — and the unit suite stays green: the card-0021 lesson biting inside drb-ac06's own flagship case.
   → **Fix:** drb-ac05 gains case (b) — a press inside a `Selected` rect whose top edge lies above `plot_area.y0` resolves to `Grab(region)`, NOT Ignore — pinning that the region hit is resolved BEFORE the plot-containment check. Constraint 3 (grab-before-brush) now states region hit *strictly precedes* plot-containment, and `Ignore` fires only when Outside the rect AND outside the plot.

3. **The pointer-shim wiring is machine-gated by fixtures the gate never runs (MEDIUM, completeness).** risk[5] named the pointer fixtures (chart_state.rs:468/484/508) as the backstop against "a missed arm silently drops drag or wipe-protection", but they are `#[cfg(all(test, feature = "gpu-tests"))]` (chart_state.rs:369); `gpu-tests = []` is opt-in with no `default` (Cargo.toml:24); the only CI workflow (license.yml) runs cargo-deny, never `cargo test`; and the stated gate is `cargo test --workspace` with no `--features`. So NONE of the ChartState pointer fixtures run in the gate. drb-ac05 unit-proves the pure *resolver's enum output* but nothing machine-gated proves `pointer_down` actually *consumes* it (honours `Grab` before the unconditional `start_brush`), nor that `pointer_move/up` take the new arms — the exact wipe/drop class the spec elevates as its reason to prefer machine defences. risk[1] even overclaimed "unit-provable" for the ordering when only the resolver was proven.
   → **Fix:** new **drb-ac13** — the shim's *consumption* of the resolver/transforms/synthesis is expressed as pure `InteractionState` state-transitions and asserted headless under the plain `#[cfg(test)]` module that DOES run in the default gate: a `Grab` at `pointer_down` preserves the rect (anti-wipe, distinct from drb-ac05's enum-only assert); a move/resize at `pointer_move` takes the transform arm; `pointer_up` yields the moved `Selected` end-state. A recorded FALLBACK covers the case a transition can't be expressed purely (run the gpu-tests fixtures + `--features gpu-tests`). Constraints 2 + 9 and risks[1]/[5] corrected to state the gpu-tests fixtures are NOT the gate's backstop — drb-ac13 is.

## Nice-to-have (LOW) — also folded into v1.1

- **Click-inside-rect silently changes the click-to-clear affordance (completeness).** Today a click anywhere in the plot `start_brush`es a zero-area brush → `commit_brush`'s click branch retracts the interval (crossfilter.rs:315-343), so a click ON the rect CLEARS. Grab-before-brush turns that press into a `Grab` → clearing now needs a click OUTSIDE the rect, and a zero-delta grab could otherwise fire a redundant re-query every click. → drb-ac05 makes StartBrush→clear explicit and drb-ac12/constraint-4 make a zero-delta grab INERT (returns `None`, no re-dispatch); a deviation records the click-to-clear semantic move (click-anywhere → click-outside — actually *more* Vega-Lite/Mosaic-faithful) for Hugh's eyeball, and drb-ac09 confirms click-outside still clears.
- **drb-ac06's enclosure guarantee is conditional (load-bearing).** `plot.y0 − DOT_RADIUS ≥ frame.y0` reduces to `insets.top ≥ DOT_RADIUS`; the 5px default clears the 4px `DOT_RADIUS` (mark.rs:197) with 1px slack, but an explicit Mosaic inset in (0,4) or a 0-inset/zero-baseline end leaves the disc overflowing. Separately, clamping to `frame_area` lets the dispatched interval bound invert PAST the data domain by up to the inset band (axi_ac03 proves the un-inset edge inverts past domain-max, chart_layout.rs:341-373). → drb-ac06 + constraint 5 scope the enclosure guarantee to `inset ≥ DOT_RADIUS`; a deviation flags the domain overshoot (row-invariant — no data lives there — but a literal predicate-value shift) for Hugh's global eyeball.
- **drb-ac11 over-claimed `invert_pixel_brush` as gate-enforced byte-untouched (scope-portability).** It lives in brightfield-ui/crossfilter.rs:919 (the crate being edited); the gate diffs only spec/sql/engine, so it cannot enforce its byte-identity — only `compile_selection` (sql/lower.rs:975) and `propagate_selection`/`contributor_predicate` (engine/lib.rs:333,293) are machine-checked. The goal + drb-ac11 contradicted the accurate constraint-1 wording ("REUSED, not modified in signature-breaking ways"). → the goal, drb-ac11, constraint 1 and the blast-radius principle now scope the MACHINE-GATED claim to the cross-crate substrate, and describe `invert_pixel_brush` + `commit_brush_release_multi` separately as reused in-place within brightfield-ui, signature-stable, verified by drb-ac07 (not the diff gate).
