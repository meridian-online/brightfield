# /orb:review-spec — Keyboard command-log (SpecEdit spine) (2026-07-14)

**Verdict: REQUEST_CHANGES → folded to spec v1.1** (same-session turnaround; blast radius concentrated on the transient-apply mechanism, clg-ac05/06/07/11 + two new ACs clg-ac15/16). The card's own #1 feasibility question — "prove a re-lowered mark query executes against the already-live session" — was pinned to a mechanism the current engine surface cannot reach; that is now corrected before implementation.

Method: a 4-lens adversarial workflow — testability, completeness, load-bearing-correctness, scope-portability — each finding then independently re-adjudicated *real-and-unaddressed* vs *already-covered* and every cited `file:line` re-verified against CURRENT source (the design memos were stale; the spec is an in-session draft not yet on disk, so AC text was adjudicated from the finding quotations cross-checked against code + the briefing recon). 10 findings survived verification (3 HIGH, 7 MEDIUM); no LOW-tier survivors this round. The survivors cluster tightly on clg-ac06 (the transient-apply mechanism) — the spec's own self-declared load-bearing risk — which is the signal the rest of the constraint set was sound and the mechanism AC needed the most hardening.

## Must-fix — RESOLVED in v1.1

1. **Transient-apply mechanism unreachable as written (HIGH, load-bearing; + MEDIUM feasibility-test, + MEDIUM fallback).** v1.0 pinned the primary mechanism as "a NEW coordinator method swaps that plot's MarkInputs" — but `MarkInput` is render-only (`"no SQL / plan-hash involvement"`, crossfilter.rs:99-100), so swapping it cannot change what SQL runs. The live `Session` emits every mark query from its OWN private `self.spec` (lib.rs:396/488/521/573) with NO public setter (grep `set_spec`/`reload`/`replace` = none), and the only executor of an externally-built `EmittedQuery` (`execute_emitted`, lib.rs:785) is private; `execute_raw_sql`/`test_execute_emitted` are both `#[cfg(test)]` (lib.rs:851/1050). So a structural edit's re-lowered query had **no production path** onto the live session — the session would re-emit the STALE SQL. The named fallback was *also* unreachable: `build_everything(spec_path: &str)` (main.rs:638) parses from DISK and builds a FRESH `Engine`/`Session`/`Connection` + re-registered views — it can neither take an in-memory `Spec` nor be "the already-live session / no new views". And the feasibility test as written ("execute on the SAME session") was satisfiable ONLY via the two `#[cfg(test)]` methods → it would go green proving nothing (the exact card-0021 silent-feature-dead trap the spec invokes).
   → **Fix:** new **clg-ac15** pins the load-bearing engine deliverable — a public `Session::reload_spec(spec, analysis)` that swaps the private `spec`/`analysis`/`mark_index_map` in place while REUSING the connection + registered views, so the existing `execute_mark` re-emits the new SQL. clg-ac06 rewritten to drive it (the app hands the mutated Spec to `reload_spec`, the coordinator re-executes + swaps marks + re-scenes). clg-ac06's feasibility leg now **drives `reload_spec` (the production seam), not a `#[cfg(test)]` executor**, asserting the executed batch changed shape. The fallback is re-scoped to a `build_from_spec(spec, base_dir)` extraction both `build_everything` and the fallback call (in-memory, no disk write) — and honestly labelled a FRESH session (state reset), not "the already-live session".

2. **Commit clobbers a dirty editor buffer — `decide_save` is not the guard the spec claims (HIGH, completeness / silent data-loss).** v1.0 asserted a dirty buffer at commit is "surfaced via `decide_save`'s ExternalConflict/RefuseUnseeded path, never clobbers". Code-verified false: `decide_save` (spec_save.rs:113-135) compares `file_now` vs `last_synced` (an EXTERNAL change); for a dirty in-app buffer with `file_now == last_synced` but `buffer != last_synced` it falls through to `_ => Write` (:133). Worse, the commit `set_value`s the serialised working Spec over the buffer FIRST (shell.rs:595-596), so `decide_save` never even sees the dirty buffer — the author's hand-typed unsaved YAML is silently lost while the spec advertises "never clobbers".
   → **Fix:** clg-ac07 + the commit constraint replaced with a **pristine-buffer gate BEFORE `set_value`**: the commit checks `buffer == last_synced` (the `should_reseed` dirtiness test, spec_save.rs:150); a DIRTY buffer REFUSES the commit with a reason (save/discard first), never `set_value` over it. `decide_save` is retained as the downstream external-file-conflict guard, explicitly NOT the dirty-buffer guard. clg-ac07 verify grows a pristine-gate leg (dirty → refuse, buffer unchanged).

3. **clg-ac05 downstream-effect proxy is vacuous for ChangeMarkType (HIGH, testability / silent no-op).** v1.0 made "re-lowering produces DIFFERENT SQL … a batch with the new mark kind" the proxy for BOTH verbs. For `ChangeMarkType` among the AC's own cited cases (dot→bar/line/rect) this is false and incoherent: all 12 of those kinds map to `SimpleLowerer` (lower.rs:883-894), whose `lower` ignores `mark.kind` entirely (lower.rs:62 — it projects `*` + param channels only), so a retype is BYTE-IDENTICAL SQL, and a `RecordBatch` has no "kind". The retype's real effect is the SCENE geometry (circles vs rectangles, dispatched by `find_renderer(renderers, m.kind)`, crossfilter.rs:833) — which the SQL/batch proxy never observes. A `ChangeMarkType` that silently keeps the old renderer would pass every headless test and be caught only by the clg-ac06 eyeball — the exact institutional lesson the spec cites (eyeball-backstop is insufficient; the headless assertion is required).
   → **Fix:** clg-ac05 SPLIT by verb on the right surface. SetChannel keeps the SQL-diff + new-batch-column + undo-revert assertion (valid — a column swap DOES change the SELECT). ChangeMarkType asserts the **scene fingerprint** changes — `scene_bytes` (path_data/draw_data via `build_multi_mark_scene`, crossfilter.rs:1012, the pure headless fingerprint) delta + undo-revert. The false "DIFFERENT SQL"/"batch with the new mark kind" wording is dropped.

4. **Count-changing AddMark/RemoveMark break the flat mark-index space (MEDIUM, completeness).** The v1.0 mechanism ("swap the plot's MarkInputs") is correct only for the two count-STABLE verbs. Add/remove change the mark COUNT, which shifts the coordinator's flat-index space the whole live path depends on: `coordinator.marks` (Vec), `mark_to_plot` (HashMap<flatIdx,plotIdx>, crossfilter.rs:218/250-254), each `LivePlot.mark_indices` (:128) — AND (the finding under-cited) the engine `Session`'s own flat `mark_index_map` (lib.rs:182) + its selection subscriber wiring (:363). A bare swap leaves those stale → a later gesture on another plot re-scenes the wrong plot or indexes out of range (silent cross-plot corruption / a dead mark) for 2 of the 5 v1 verbs.
   → **Fix:** new **clg-ac16** + the count-split constraint: count-stable ChangeMarkType/SetChannel do the in-place swap; count-changing AddMark/RemoveMark rebuild the coordinator maps AND the engine `mark_index_map` (via `reload_spec`) + subscriber wiring (or route through the `build_from_spec` fallback). Verify: after an AddMark, a gesture on ANOTHER plot still routes correctly (`mark_to_plot`/`mark_index_map` integrity).

5. **clg-ac06 vs clg-ac11 imply opposite coordinator semantics — durability left open (MEDIUM×2, completeness + scope-portability).** clg-ac06 mutates the coordinator like `c` (a DURABLE mark swap), which makes an applied edit SURVIVE later gestures; clg-ac11 asserted a committed edit REVERTS on the next gesture "because the coordinator still holds LAUNCH marks". But every commit is preceded by the transient apply, so on the commit path the coordinator is ALWAYS already mutated — the revert claim is inverted. The analogy was also backwards: the accepted "cycled-scheme-persists" limitation is a PERSISTENCE, not a revert (cycle_scheme durably mutates `self.marks`+`launch_scales`, crossfilter.rs:456-464; its own doc says the change *persists* until restart, :435-437; the watcher swaps scenes only, main.rs:1214-1226).
   → **Fix:** the transient apply is pinned as a **DURABLE coordinator mutation**, so a within-plot edit — transient AND committed — PERSISTS across gestures (correct, matching `c`). clg-ac11 / out_of_scope / risks rewritten: command-log edits do NOT revert; the RESIDUAL deferred boundary is an EXTERNAL disk edit arriving via the watcher (not the command log), which never rebuilds the coordinator. A static dashboard round-trips either way.

6. **clg-ac11 gate-classifier tested only in isolation — no agreement with the real gate (MEDIUM, testability).** clg-ac01 places the classifier in gpui-free brightfield-spec, but the real gate is app-binary-local and unreachable from it: `chrome_divergence` is a private fn in the `brightfield` binary (main.rs:558), `same_layout` an inline closure (main.rs:1166-1175), and brightfield-app has NO `[lib]` target (Cargo.toml: only `[[bin]]`). So the classifier must REIMPLEMENT both gates from the spec/analysis representation; if it under-refuses (says gate-clean where `chrome_divergence` would trip on a new colour legend — literally an open question in the briefing), a committed edit silently bounces to "restart to apply" and every headless test still passes.
   → **Fix:** clg-ac11 grows an **agreement test** in a brightfield-app `#[cfg(test)]` module (the crate that CAN see the gate, as the existing main.rs:2471+ tests do): build the `ChromeSnapshot`/plot geometry from the MUTATED spec via the app's own build path and assert the spec-layer classifier's verdict EQUALS `chrome_divergence`/`same_layout` on the same inputs — ideally a single shared predicate so drift is impossible.

7. **Transient re-scene shows a widen-unioned / stale axis (MEDIUM, scope-portability).** v1.0's constraint "build_plot_scene re-infers scales, so a changed kind/channel re-scenes correctly" mis-states the code: `build_plot_scene` folds a fresh inference WIDEN-ONLY against the plot's immutable `launch_scales` (`anchor_scale` unions domains, `lmin.min(fmin)`/`lmax.max(fmax)`, scale.rs:360). A channel rebind (x: colA→colB) is neither a subset nor a param-widen, so the preview axis UNIONS colB's domain with the STALE launch colA domain — a wrong axis for exactly the edits this card exists to make, and clg-ac06's "non-empty batch" assertion passes even so. Self-heals on commit→reload, but the preview is the whole see-then-commit value loop.
   → **Fix:** the transient apply RESETS the affected plot's launch anchor to the re-lowered fresh inference BEFORE `build_plot_scene` (matching what a commit→reload's fresh `build_everything` computes); clg-ac06's in-app leg now checks a CLEAN axis (not just a non-empty batch). The mis-stating constraint is corrected.

## Strengths (verifier consensus)

- **The spec's own card-0021 silent-no-op discipline is what caught its worst AC.** clg-ac05's insistence on "a REAL downstream effect, not a log append" is exactly the lens that exposed the vacuous ChangeMarkType SQL-proxy — the invariant is sound and legible enough to catch its own violation.
- **Every mechanism claim was `file:line`-pinned**, which made adversarial verification fast and the corrections precise: the false ones (MarkInput-swaps-SQL, decide_save-guards-dirty-buffers, committed-edit-reverts, build_plot_scene-re-infers-cleanly) fell to a direct source read rather than argument.
- **Confinement-as-a-hard-edit-time-gate** (refuse, never silently bounce) is the right posture; the only gap was proving the reimplemented classifier agrees with the real gate — a test, not a redesign.
- **The transient-vs-commit transport split with a no-disk invariant** is a clean, honest architecture; the review's net effect is to *name the seam the transport needs* (`Session::reload_spec`) rather than to challenge the design.

## Addendum — out-of-band verify fold (clg-ac04, LOW)

During the review the parallel verify agents (whose prompts lacked the on-disk spec) queried the orchestrator for AC text; one adjudicated a LOW the main verify pass did not separately surface and it was folded by hand into v1.1: **clg-ac04's verify carried a vacuous assertion** — "assert the two dots' flat indices differ" is a tautology, because the flat index is assigned by `.enumerate()` over the collected marks (lib.rs:1068), so any two distinct marks always differ regardless of whether AddMark produced a correct tree (the "unique index-map keys" clause is likewise true-by-construction from the item-ordinal prefix). Fix: dropped the tautology; added an explicit **cardinality** assertion (AddMark → plot item count +1); kept the RemoveMark→AddMark stale-path guard; and named the **test crate-home** (brightfield-engine, since `build_mark_index_map` is engine-private at lib.rs:1061 and unreachable from a brightfield-spec test — or expose a gpui-free ordinal resolver in brightfield-spec). Separate from the "positional-addressing renumber" concern dropped above (that was about the reducer's *targeting*; this is about the *test's* teeth).
