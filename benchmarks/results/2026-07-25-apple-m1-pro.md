>
> **The cap this record was produced under** was `FRAME_DRAWN_ROW_CAP` =
> 1,000,000 drawn primitives — derived from the storage-buffer binding size at
> its conservative 128 MiB default, at ~128 bytes per primitive. That reasoning
> was wrong twice over: the adapter reports 4 GiB, and a far lower ceiling was
> always underneath it. Today's cap is 100,000.
>
> **The measured ceiling — the number this record never stated.** The renderer
> stops drawing between **104,600 dots (inked)** and **104,800 dots (blank:
> exit 0, frame written, every pixel `rgba(0,0,0,0)` — blank, not thinned)**.
> It is set by vello's **fixed 2^21-element `seg_counts` buffer** and is **not a
> device limit**: no adapter limit moves it. Past it vello sets a `failed` bit
> in a GPU-side counter, skips coarse and **returns `Ok`**, so nothing raised an
> error when these three cells were timed. A second, exact ceiling sits above:
> `bin_data` is 2^18 = 262,144 elements, and the encode underflows a `u32` at
> 262,102 dots in that fixture (262,144 − 42 paths of frame, grid and axis rule).
>
> **The “Rows with no frame cells, and why” list below is superseded** — it
> names the 1,000,000 cap and blames the scene buffer. Both are corrected here.

## Interaction latency and frame time vs row count

`direct` disables the automatic pre-aggregation layer; `cubed` is the shipped configuration. Identical code either side of the toggle — the delta is the layer. `cube` shows what the enabled run's layer did: cubes built / **mark re-queries** served from a cube. The second number is not a step count: the engine counts one hit per mark it serves, so a scenario filtering two subscribing marks records two hits per drag step and a twenty-step suite reads `2/40`. `Drag` is the gesture the timed steps imitate: a **brush** moves both interval endpoints inside a chart and exempts its own plot (crossfilter); a **slider** pins its lower end, advances one handle across fixed stops, and filters every view including the contributor's (intersect) — so a slider step re-queries one more view than a brush step at the same row count.

**`Arrow held` is the figure to quote.** It is exact and deterministic — the summed size of every materialised chunk the compose holds at once, read from the batches themselves — so it is the same on any host and reproduces run to run.

`Compose peak RSS` is the whole process's high-water mark across the first full compose — every mark executed, every Arrow chunk assembled, the scene built — sampled from the OS (ps -o rss (~5ms resolution)). Both configurations' windows are shown because they measure the SAME compose work: the first present precedes any interaction, so no cube exists yet either side of the toggle. Each cell is therefore a SINGLE sample of a whole-process quantity, and the gap between the pair is this measurement's run-to-run noise — across the rows above it reaches 2.4x (crossfilter-dots @ 100000 rows). **Do not quote a peak without that spread.** The pre-compose floor is not a monotone baseline either: the OS reclaims pages between windows, so it falls as often as it rises and the growth over it is not the compose's cost. `rss_before_mib`, `rss_peak_mib`, `rss_growth_mib` and `rss_samples` are in the JSON per configuration for anyone who wants them.

### Rows with no frame cells, and why

A blank frame cell is not a fast frame. These rows produced no frame at all:

- **crossfilter-dots @ 1000000 rows** — 2000000 row-level primitives exceeds the 1000000 the renderer can encode in one scene buffer — the frame does not render at all
- **brush-density @ 10000000 rows** — 10000000 row-level primitives exceeds the 1000000 the renderer can encode in one scene buffer — the frame does not render at all
- **brush-binned-density @ 10000000 rows** — 10000000 row-level primitives exceeds the 1000000 the renderer can encode in one scene buffer — the frame does not render at all
- **crossfilter-dots @ 10000000 rows** — 20000000 row-level primitives exceeds the 1000000 the renderer can encode in one scene buffer — the frame does not render at all
- **crosswalk-confidence @ 207099 rows** — fixed-scale scenario: engine suites only, no frame suites
