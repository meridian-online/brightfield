## Findings

### [LOW] Code duplication between emit_query and emit_query_with_passes
**Category:** performance
**Description:** `emit_query_with_passes` is a near-verbatim copy of `emit_query` with an additional `extra_passes` parameter. The original `emit_query` constructs an empty `passes` vec and calls `apply_passes`. These two functions share ~20 lines of identical logic (collect_marks, find_lowerer, lower, render).
**Evidence:** `crates/brightfield-sql/src/emit.rs:269-310` vs `crates/brightfield-sql/src/emit.rs:317-354`. The only difference is the passes argument.
**Recommendation:** Refactor `emit_query` to delegate to `emit_query_with_passes` with an empty slice. Not blocking; the duplication is small and low-risk.

### [LOW] f64 formatting in SQL predicates uses Display, not a SQL-safe formatter
**Category:** edge-case
**Description:** `NavigationFilterPass::apply` formats f64 values via `{}` (Rust Display) into SQL predicate strings. Display for f64 can produce scientific notation (e.g., `1e-10`) for very small or very large values. DuckDB parses scientific notation in SQL literals, so this is not a bug. However, if a domain somehow produced `NaN` or `inf` (e.g., from a zero-span domain under zoom), the emitted SQL would contain invalid literals.
**Evidence:** `crates/brightfield-sql/src/navigation_filter_pass.rs:74-75`: `format!("\"{}\" >= {}", filter.column, filter.min)`.
**Recommendation:** Consider adding a guard in `apply_zoom` or `from_extents` that rejects NaN/inf values. Not blocking; the current call chain (scale inverse on finite domains, zoom factor > 0) cannot produce these values in practice.

### [LOW] Debounce test relies on real elapsed time
**Category:** test-gap
**Description:** `nav_ac08_debounce_settles_after_duration` uses `thread::sleep(5ms)` to wait for a 1ms debounce timer. This is reliable in practice but technically timing-dependent. The spec review flagged this same concern.
**Evidence:** `crates/brightfield-ui/src/interaction.rs` test `nav_ac08_debounce_settles_after_duration` uses `Duration::from_millis(1)` debounce + `sleep(5ms)`. The 5x margin is generous but CI under heavy load could theoretically fail.
**Recommendation:** Acceptable as-is. If flakiness is observed, introduce a mockable clock. The 5x margin makes this unlikely to fail in practice.

### [LOW] emit_query_with_passes does not compose built-in passes with extra passes
**Category:** bug (latent)
**Description:** `emit_query` applies a hard-coded empty passes vec. `emit_query_with_passes` applies only the caller-provided `extra_passes`, not a combination of built-in + extra. Today this is a no-op since built-in passes are empty (`vec![]`). When built-in passes are added (e.g., pre-aggregation, M4), `emit_query_with_passes` will skip them unless it is updated.
**Evidence:** `crates/brightfield-sql/src/emit.rs:294-296` (empty built-in passes in `emit_query`) vs `crates/brightfield-sql/src/emit.rs:344` (only extra_passes applied in `emit_query_with_passes`).
**Recommendation:** When built-in passes are added, ensure `emit_query_with_passes` composes them with extra passes. This is a future concern, not a current bug.
