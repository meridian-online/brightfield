Brightfield keyboard grammar — v1 candidate keymap

A selection-first grammar: scope is where focus sits on the component tree, a bare verb acts on the focused node, and the single prefix g broadcasts a runtime verb to the whole dashboard. Every binding below is scored on the three axes you set — frequency · mnemonic · convention — with a fourth motor-cost lens folded into conflicts. Derived, not hand-picked; here to be reacted to.

12-agent research· refs: VisiData · vim · Helix/Kakoune · Zed · Linear/Superhuman · KLM/GOMS· synthesize → 3× adversarial → reconcile
01

The model — scope is focus, not a prefix

The pivotal question ("does the prefix re-target or modify the same target?") dissolved: the answer is neither. You navigate focus down/across the ComponentPath tree (Helix/ranger-style), and the bare verb acts wherever focus lands. Only g survives as a prefix — and it always resolves to root, so it can never mean "delete my parent." z is dropped entirely (Enter-dive already gives containment-down more cheaply), which frees it for future zoom and kills the z=zoom collision.

hl

Depth. l / Enter dive into a child; h / q pop to the parent. Ranger/miller-columns convention — hierarchical, not spatial.

jk

Siblings. j / k step across siblings at the current altitude. The focus ring + breadcrumb show where focus landed (the tree has no honest screen direction).

f

Bare verb = act on focus. f filters the focused plot. Off its altitude it rejects with a visible reason — never a silent no-op.

gf

g = broadcast to dashboard. g f = cross-filter every view. Runtime-only, always root — structure never rides g.

03

How it stays learnable while staying terse

The release valve: discoverability is additive layers that never lengthen the expert path. Cryptic-but-fast keys are affordable because the palette teaches by meaning and shows the key inline.

Space Palette

Fuzzy over longname + help, focus-scoped, frequency-ranked. Each row shows its bound key inline — the recognition→recall handoff.

g … Which-key

After g (and proactively the first bare f), an overlay teaches the rule — "same verb, whole dashboard" — before the prefix is known.

◎ Breadcrumb + focus ring

Always shows the current altitude, any pending prefix, and a g-verb's resolved target (root) — scope is shown pre-commit, never implied.

? Help sheet

Every verb: longname, bindings, scope, help — the greppable master index and reverse key map.

04

The calls that are yours

Everything above has a recommendation baked in. These are the genuine forks the research surfaced rather than silently took.

DECISION · scope ceiling

How far does v1 reach?

The ceiling is set by two deferred builds — the command log (gates every spec-edit verb + undo) and the focus model (canvas focus is mouse-only today, so it's a mandatory prerequisite even for the "cheap" card).

recommendedNavigate + palette + focus model + built runtime verbs. All edit letters reserved & visible. The honest first card.
+ oneAlso ship c = set-colour-scheme as live-preview via renderer_override (transient, no log).
biggerPull the command log into this card — unlocks the full edit family + undo. Materially larger.
DECISION · the g convention

Does g mean "broadcast to dashboard"?

It diverges from the strong g = "go to / jump" convention (Gmail, Linear, vim gg). The research keeps it because cross-filter-all is frequent and already built, carried by a visible breadcrumb + which-key.

recommendedAccept g = dashboard-broadcast, taught by breadcrumb + which-key.
altRealign g = "go to a component" and give cross-filter-all a different key.
DECISION · channel altitude

Does focus descend to the channel in v1?

v1 floor is proposed as mark — dive, set-channel and colour-at-channel all stop there, matching the deferred channel focus target. Channel edits live in the palette until a later card.

recommendedFloor at mark. Channel edits via palette only for now.
biggerBuild a mark→channel focus target this card — unlocks channel-level bare verbs.
