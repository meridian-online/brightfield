## Findings

### [MEDIUM] ac-04 partial failure test cannot exercise mixed Ok/Err — both marks fail

**Category:** test-gap
**Description:** AC-04 specifies "one valid (dot with data.from) and one invalid (rect, unsupported lowerer)" producing one Ok and one Err. The v2 test (`rpw2_ac04_partial_failure_independent_dispatch`) improved over v1 by wiring both marks into the subscriber graph via `filterBy: $brush`, so both are dispatched (results.len() == 2). However, since `default_lowerers()` returns an empty registry, ALL marks fall through to `DefaultLowerer` which returns `UnsupportedMark`. Both dot and line produce `Err(EmitFailed(UnsupportedMark))`. The test proves independent dispatch (both marks get their own result entry regardless of the other's outcome) but cannot prove the mixed Ok/Err case because no mark lowerer is registered yet.

**Evidence:** `crates/brightfield-sql/src/lower.rs:49-52` — `default_lowerers()` returns `vec![]`. `crates/brightfield-sql/src/lower.rs:37-42` — `DefaultLowerer` always returns `UnsupportedMark`. `crates/brightfield-engine/src/lib.rs:1160-1210` — test asserts `results.len() == 2` but does not (and cannot) assert one Ok and one Err.

**Recommendation:** Acceptable as-is. The structural independence property (both dispatched, neither blocked by the other) is verified. The true mixed Ok/Err test requires a registered lowerer (card 0001, SimpleLowerer). When card 0001 lands, this test should be strengthened to assert one Ok and one Err by using dot (supported) + rect (unsupported). This is not blocking because the `continue` pattern in `propagate_param` is structurally identical to the proven pattern in `update_param`.

### [LOW] execute_mark passes None when param_state is empty

**Category:** edge-case
**Description:** `execute_mark` conditionally passes `None` vs `Some(&self.param_state)` based on `self.param_state.is_empty()`. This preserves backward compatibility — specs with no params emit identical queries to pre-change code. If a param were added via `propagate_param` and the map later became empty (not currently possible since there is no remove API), the `is_empty()` guard would revert to None semantics. Non-issue today.

**Evidence:** `crates/brightfield-engine/src/lib.rs:167-171` — the `is_empty()` guard.

**Recommendation:** No action required.

### [LOW] emit_query ignores param_values argument

**Category:** assumption
**Description:** The `_param_values: Option<&ParamValues>` parameter in `emit_query` is prefixed with `_` and unused. The param_state plumbing in `execute_mark` and `propagate_param` passes params to `emit_query`, but they are silently ignored. SQL emission does not actually inject param values into queries yet. This is expected — param injection into SQL requires card 0001's SimpleLowerer. The coordinator's state management is correct and ready to feed real param injection once the lowerer supports it.

**Evidence:** `crates/brightfield-sql/src/emit.rs:272` — `_param_values: Option<&ParamValues>`.

**Recommendation:** No action required. This is a known integration gap between cards 0005-v2 (coordinator) and 0001 (lowerer). The plumbing is in place.
