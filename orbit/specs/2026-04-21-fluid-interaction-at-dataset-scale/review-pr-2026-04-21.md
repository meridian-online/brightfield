## Findings

### [MEDIUM] F1: ac-08 has zero test coverage — emit_query/emit_all_queries untested
**Category:** test-gap
**Description:** The spec's ac-08 verification explicitly requires: "Integration test with a synthetic Spec containing an Unimplemented mark -> UnsupportedMark." Neither `emit_query` nor `emit_all_queries` has any test — unit or integration. The functions exist in `crates/brightfield-sql/src/emit.rs` (lines 269-322) and are public API, but `grep -r emit_query crates/brightfield-sql/tests/` returns zero hits, and there are no `#[cfg(test)]` blocks in emit.rs exercising them.
**Evidence:**
```
$ grep -r 'emit_query\|emit_all_queries' crates/brightfield-sql/tests/
(no output)
```
The 39 `dfir_` tests cover ir.rs, lower.rs, render.rs, binding.rs, passes.rs, and conform.rs — but not the `emit_query` orchestration path.
**Recommendation:** Add at least one integration test in `crates/brightfield-sql/tests/emit_tests.rs` (or a new file) that constructs a `Spec` with a mark, calls `emit_query(spec, 0, None)`, and asserts `Err(EmitError::UnsupportedMark { .. })`. This also validates the collect_marks -> lower -> passes -> render -> hash orchestration chain end-to-end.

### [LOW] F2: Exit condition "sqlparser-rs parses every SQL string emitted by render_query in tests" not enforced
**Category:** test-gap
**Description:** The spec's exit conditions include "sqlparser-rs parses every SQL string emitted by render_query in tests." The render.rs tests (8 tests) use only string assertions (`contains`, `starts_with`, `eq`) but never pass the emitted SQL through `sqlparser::parser::Parser::parse_sql`. The `conform.rs` module provides `parse_and_normalise` for exactly this purpose, but it is not called from render tests.
**Evidence:** `crates/brightfield-sql/src/render.rs` — the `#[cfg(test)]` module imports only `SourceDdl` and `SourceKindTag`; no sqlparser imports. The `conform::parse_and_normalise` function exists but is unused in render tests.
**Recommendation:** Add a `parse_and_normalise` call to each render test (or a dedicated round-trip test) that asserts the emitted SQL is valid DuckDB syntax. This is low severity because the current SQL strings are simple and obviously valid, but the exit condition contract is not met.

### [LOW] F3: legends.layer2.expected.sql is empty (0 bytes)
**Category:** edge-case
**Description:** The `legends.yaml` curated spec has no `data:` section, so the emitter produces zero DDL statements. The corresponding `legends.layer2.expected.sql` fixture is 0 bytes. The conformance check passes because `canonicalise_ddl(&[])` returns an empty string, which matches the empty file read. This is correct behaviour but worth documenting — an empty fixture is intentional, not an oversight.
**Evidence:** `wc -c crates/brightfield-conformance/vendor/curated/yaml/legends.layer2.expected.sql` → 0 bytes. `legends.expected.yaml` has `layer_2: pass`.
**Recommendation:** Add a one-line comment at the top of the file (`-- no data sources`) or document the intentional empty fixture in the generate_layer2_fixtures test. No code change needed.

## Honest Assessment

This is a well-structured infrastructure delivery. The QueryPlan IR, predicate model, selection compilation, binding model, pass pipeline, and sqlparser conformance utilities are all cleanly implemented with comprehensive unit tests (39 new `dfir_` tests, well above the 23 threshold). The code respects all 9 hard constraints — no I/O in brightfield-sql, EmitError is the single error type, no marks are flipped to Implemented, and existing card 0004 tests are unbroken. The one substantive gap is the missing integration test for `emit_query`/`emit_all_queries` (ac-08), which is the public orchestration entry point that wires together lowering, passes, rendering, and hashing. This is a straightforward fix — one test asserting `UnsupportedMark` on a synthetic spec would close it. The sqlparser validation gap (F2) is lower risk but leaves an explicit exit condition unmet.
